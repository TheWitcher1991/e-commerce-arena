# Инструкции для агентов

## Общие правила

- Сначала изучите профильные `README.md`, `DESIGN.md`, `docs/` и затрагиваемые исходники. Продуктовые требования берите из документации проекта; неизвестные продуктовые детали не выдумывайте.
- Сохраняйте текущие соглашения и не переписывайте несвязанные части проекта.
- Не добавляйте секреты и реальные локальные настройки в репозиторий. Используйте соответствующий `.env.example` как шаблон.
- Не запускайте frontend, backend, Docker Compose, БД, миграции и тесты без явного запроса пользователя. Допустимы статические проверки, если они не стартуют сервисы и не изменяют данные; сообщайте, что именно проверено.
- Не утверждайте, что функциональность проверена в браузере или интегрирована с сервером, если это не было фактически проверено.

## Frontend

- Стек: Next.js App Router, React, TypeScript, TanStack Query, Tailwind CSS v4, pnpm.
- Следуйте Feature-Sliced Design и правилам импорта в `frontend/ARCHITECTURE.md`: route adapters в `src/app`, экраны в `src/screens`, затем `widgets → features → entities → shared`.
- Импортируйте публичный API среза через `index.ts`; не создавайте циклических или направленных вверх зависимостей.
- Перед визуальными изменениями изучите `DESIGN.md` и `skills/make-interfaces-feel-better/SKILL.md`.
- Адаптеры browser storage — демонстрационные. Не представляйте их как авторизацию, серверное хранение или контроль прав.
- Используйте `pnpm`, сохраняйте `frontend/pnpm-lock.yaml` в актуальном состоянии.

## Backend

- Стек: Python 3.12+, FastAPI, Pydantic v2, SQLAlchemy 2, PostgreSQL, Alembic.
- Держите API-валидацию в схемах, авторизацию — в dependencies/services, а изменения схемы БД — в новых ревизиях Alembic.
- Изменения БД должны иметь явные ограничения, индексы и правила удаления, соответствующие моделям и бизнес-правилам.
- Не создавайте таблицы автоматически при импорте/старте приложения; схема управляется миграциями.
- Не ослабляйте проверку роли и принадлежности пользователя к занятию/команде ради упрощения UI.
- При изменении моделей синхронно обновляйте Alembic-миграцию и backend-документацию.

## Docker и конфигурация

- Корневой `docker-compose.yml` предназначен для локального стека. Сервис миграции запускается отдельно и только по явной команде.
- Не встраивайте секреты в Dockerfile, образы или Compose defaults; добавляйте только безопасные шаблоны в `.env.example`.
- После изменений Docker-конфигурации можно проверять `docker compose config`; эта команда не должна запускать контейнеры.
- Не используйте `docker compose up`, `build` или `run` без явного запроса пользователя.
